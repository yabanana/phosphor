# F27 — Runtime di gioco ed ECS con riuso Bevy

La roadmap resta l’autorità delle caselle. Questo piano specifica il lavoro task per task; non dichiara risultati futuri. I candidati restano selezionabili e non bloccano la baseline. ## Architettura e decisioni fissate

Prima scelta host Rust con crate Bevy effettive e renderer C++ Metal. Un mondo autorevole, un loop/clock e un budget pool; ABI C versionata passa snapshot/delta POD in batch, mai puntatori Rust senza lifetime o FFI per componente. ECS ispirato a Bevy resta alternativa con perdita compatibilità esplicita.

## Prerequisiti e confini

Baseline richieste: [F5](F5.md), [F8](F8.md). Sono contratti utilizzabili, non la chiusura di interi cataloghi o di certificazioni hardware esterne.
Integrazione successiva con [F23](F23.md): Coordinate/reuse scheduler baselines; no dependency on custom heterogeneous scheduler or kernel research.

## Spike e scelte condizionali

Vertical slice headless world→transform→extraction→SceneStore con plugin non-render, poi stesso frame Metal. Release e feature Bevy fissate alla prova; confronto byte/copie, lifecycle e costo al crescere delle mutazioni.

## Implementazione e accettazione per task

### F27.1 — Scelta host

**Ambito:** Scelta ECS con priorità al riuso diretto di `bevy_ecs` e `bevy_app`/reflection/moduli necessari, affiancati al renderer C++ Metal; prova di integrazione contro ECS corrente. Alternativa C++ deliberatamente ispirata a Bevy, anche su EnTT/flecs, solo con motivazione e costo di compatibilità espliciti; non promettere plugin Rust compatibili con un clone [R112–R113]

**Stato di pianificazione:** Da implementare o completare; stato dettagliato nella roadmap.

- **Implementazione:** Provare bevy_ecs/app/reflection con minimal feature set contro ECS corrente; motivare eventuale EnTT/flecs/C++ alternativo.
- **Verifica/accettazione:** Una demo reale e matrice plugin/dependency; decisione include manutenzione e compatibilità, non solo microbenchmark query.
- **Evidenza da conservare:** commit e artefatti del pacchetto, comando/configurazione della prova e risultato nel log pertinente; un esito non eseguito rimane dichiarato tale.

### F27.7 — Bridge ABI

**Ambito:** Prototipo del confine Rust/C++: snapshot e delta in batch verso GPU scene F5, entity handle con generazioni, ownership/retirement, errori e shutdown; un solo mondo autorevole, clock/event loop e gestione dei pool espliciti, senza chiamate FFI per ogni componente nel ciclo caldo

**Stato di pianificazione:** Da implementare o completare; stato dettagliato nella roadmap.

- **Implementazione:** Header POD versionato con size/alignment, batch delta, release callback/error code e retirement.
- **Verifica/accettazione:** Layout Rust/C++, create/delete/reuse, overflow, panic/exception contenuti e shutdown durante upload.
