## 1. Transmission (specular, refractive glass and liquids)

### T1. Opaque colour pyramid, screen-space refraction (the glTF baseline)

1. **Algorithm / inputs.** Render all opaque (and optionally earlier transparent) geometry into an HDR colour target; build a full mip chain; then draw transmissive surfaces sorted back to front, each sampling that pyramid at a refracted screen position, with the mip chosen from roughness. Inputs: opaque colour pyramid captured *before* transmissive surfaces, projection matrices, per-fragment thickness (factor/texture) and attenuation data. Optional depth of the back face (T2). The glTF spec itself states that the minimum expectation is "render only opaque objects" through a transmissive material, and that IBL-only is likely to fall short. [V] https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_transmission/README.md (Implementation Notes)
2. **glTF mapping.** `transmissionFactor/Texture` = lerp weight between diffuse BRDF and specular BTDF; `roughness` = blur (microfacet refraction), scaled by IOR; `ior` = refraction bend and Fresnel; `KHR_materials_volume.thicknessFactor/Texture` (G channel, mesh-local units) = path length; `attenuationColor/Distance` = Beer-Lambert (`sigma_t = -ln(c)/d`). Thin-walled (`thickness = 0`) means no macroscopic refraction, only roughness blur. [V] KHR_materials_volume README (`603619e…`/main), KHR_materials_transmission README.
3. **Costs / limits.** Cost = one extra HDR colour copy + mip generation per frame plus one fetch per transmissive pixel. No published GPU number from Khronos/Filament/HDRP for this step [U: none found]. Limits (all [V] from HDRP and Khronos text): single layer only (HDRP: "refractive objects won't be visible through other refractive objects" because the colour buffer is the first pyramid containing only opaques, https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@14.0/manual/reflection-refraction-hierarchy.html); lookups past the screen edge or behind the refractor's own depth have no data (fallback chain in HDRP: screen colour, then reflection probe, then sky, then black); objects in front of the refractor leak into the refraction unless masked by depth (UE exposes "Refraction Depth Bias" for this, https://dev.epicgames.com/documentation/en-us/unreal-engine/using-refraction-in-unreal-engine [V]).
4. **Khronos Sample Renderer, exactly** (all `cc3d5ff…`):
   - Framebuffer: `renderer.js` ~L1134-1235: "If any transmissive drawables are present, render all opaque and transparent drawables into a separate framebuffer" (MSAA RT, `linearOutput`, `TRANSMISSION_PASS 1` define, environment drawn first), blit/resolve to `opaqueFramebuffer`, then `generateMipmap(TEXTURE_2D)` (L~1233). Transmissive drawables are then drawn depth-sorted (`sortPrimitivesByDepth`, L~1347) into the main framebuffer sampling `opaqueRenderTexture`. So transmissive objects do **not** appear inside each other's refraction. Default RT size 1024x1024 (`opaqueFramebufferWidth/Height`). [V]
   - `shaders/ibl.glsl` `getTransmissionSample()`: `lod = log2(u_TransmissionFramebufferSize.x) * applyIorToRoughness(roughness, ior)`; `textureLod(u_TransmissionFramebufferSampler, uv, lod)`. [V]
   - `shaders/functions.glsl` `applyIorToRoughness(r, ior) = r * clamp(ior*2 - 2, 0, 1)` (IOR 1.0 gives no blur, IOR 1.5 gives the full roughness; comment in file). [V]
   - `ibl.glsl` `getIBLVolumeRefraction()`: `transmissionRay = getVolumeTransmissionRay(n, v, thickness, ior, modelMatrix)`; exit point `position + ray`; projected with `proj*view` to NDC to uv; sample (above); then `applyVolumeAttenuation(light, length(ray), attenuationColor, attenuationDistance)`; result multiplied by `baseColor`. Optional dispersion: per-channel IOR spread `halfSpread = (ior-1)*0.025*dispersion`. [V]
   - `punctual.glsl` `getVolumeTransmissionRay()`: `refract(-v, n, 1/ior)`, normalised, times `thickness * modelScale` (per-axis length of model matrix columns, thickness is in local space). `applyVolumeAttenuation`: `pow(attenuationColor, distance/attenuationDistance)`, with `attenuationDistance == 0` meaning +inf (no attenuation). [V]
   - Punctual lights through glass (`getPunctualRadianceTransmission`): light vector mirrored about the normal, `D_GGX * V_GGX` with IOR-scaled roughness, times `baseColor`; light position shifted by the refracted exit ray (`pointToLight -= transmissionRay`). [V] (`punctual.glsl`, `pbr.frag` ~L500-525)
   - Diffuse transmission (`KHR_materials_diffuse_transmission`, `pbr.frag` ~L331-339, L477-496): IBL `getDiffuseLight(-n) * diffuseTransmissionColor`, per-light `NdotL(-n) * BRDF_lambertian(color)` for lights behind the surface; optional volume attenuation with `thickness * mean(modelScale)`; then `f_diffuse = mix(f_diffuse, transmissionIBL, diffuseTransmissionFactor)` and `l_diffuse *= (1 - factor)`. No scene-geometry shadowing of the back light beyond what the renderer already gives. [V]
5. **Visibility-buffer fit.** [A] Transmissive primitives must be removed from the opaque visibility pass (the vis-buffer stores one triangle per pixel, opaque and alpha-tested only). Opaque is resolved and lit as today into the HDR colour; the pyramid is built from the lit result; transmissive geometry is a second, forward-style pass (or a second vis-buffer layer resolved by compute) that fetches the pyramid. The pyramid must be the *final composited* radiance (DI+GI+specular+denoised reflections), i.e. built after the existing composition. With RT available the pyramid is still the cheap source for roughness-blurred background.

### T2. Back-face depth / thickness estimation (Wyman image-space refraction, HDRP Sphere/Planar/Thin, Filament solid/thin)

1. **Algorithm.** Wyman: a prepass renders back-face depth and normal; at the front hit `P1` compute `t1 = refract(v, n1, eta)`, approximate the exit point `P2 ≈ P1 + d~ * t1` with `d~` = difference between front depth and back-face depth at the same pixel, refract again with the back-face normal, then fetch the background at the projected `P2`. [V via Avalanche's description in RTG II ch. 29 §29.2, https://doi.org/10.1007/978-1-4842-7185-8_29 ; original paper: C. Wyman, "An Approximate Image-Space Approach for Interactive Refraction", SIGGRAPH 2005, pp. 1050-1053 [U: not read; venue from search snippets]]. Inputs: front depth, back-face depth + normal (extra raster pass with reversed depth test, ~one more depth/normal target), colour pyramid.
   Engine variants that need no back-face pass: HDRP **Sphere** (the object is a sphere of diameter = thickness, tangent at entry; second refraction on that sphere's normal; background upside-down for spheres), **Planar** (exit is a parallel plane, ray bent back to the entry direction, offset only), **Thin** (planar with thickness fixed at 5 mm). [V] https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@14.0/manual/refraction-models.html . Filament `refractionType: solid` (sphere of radius `thickness` tangent at entry) / `thin` (flat slab of `thickness`); `refractionMode: cubemap` (IBL only, no scene objects) vs `screenspace` (refracted rays assumed to leave parallel to view direction). [V] https://google.github.io/filament/Materials.md.html (sections refractionMode, refractionType, Index of refraction)
2. **glTF mapping.** Exactly the Sample Renderer's approach: glTF `thicknessFactor/Texture` replace the back-face pass (the spec calls the thickness map a baked substitute, "ray-tracers should ignore the thickness texture and use the actual, ray-traced distance", KHR_materials_volume README [V]). Back-face depth can *replace* the thickness texture; mathematically glTF's `thickness` is the distance along the entry normal, not along the view ray [U for exactness; spec text read, not the derivation].
3. **Costs / limits.** One extra depth/normal raster pass (cost not published). RTG II ch. 29 Fig. 29-1 (RTX 2070 SUPER, 1920x1080, one glass object): image-space refraction 0.07 ms vs RT 1 ray 0.67 ms / 2 rays 1.27 ms / 3 rays 1.58 ms; hybrid 2 post-rays 0.92 ms, 2 pre-rays 1.30 ms. [V] Limits: exact only for closed objects with two depth layers; "highly inaccurate" for concave objects with more than two layers (donut etc.); single refractive layer; screen-edge misses. [V] RTG II ch. 29 intro and abstract.
4. **Sample Renderer.** Does **not** use back-face depth for plain transmission (only thickness factor/texture). It does render a back-face depth target (`scatter_back_depth.frag`, depth-only, `scatterBackDepthTexture`) for the scatter extension (see S5). [V]
5. **Vis-buffer fit.** [A] Needs closed meshes. For the chess pieces (closed, convex-ish) a back-face depth+normal pass over only the transmissive instances is cheap (a handful of draws). A ray-traced alternative (T3) removes the pass.

### T3. Ray-traced refraction (inline or pipeline rays; Metal intersectors)

1. **Algorithm.** Treat the transmissive surface as a reflection-like secondary ray: at a primary hit on glass, refract by Snell (rough glass: sample the GGX BTDF), continue to the exit (back face of the same closed mesh), apply Beer-Lambert `exp(-sigma_a * hitT)` on back hits, refract again, continue until an opaque hit or max depth; then take radiance of that opaque hit from the existing shading (G-buffer/vis-buffer radiance fallback). Inputs: TLAS with transmissive geometry flagged, instance/material data for the glass, ability to evaluate shading at the end hit. RTG II ch. 11 (Zhang, NVIDIA): "path tracing-style translucent pass": primary ray refracted on entering/leaving, `throughput *= exp(-absorptionCoefficient * hitT)` on back hits, fetch G-buffer radiance when the ray lands on a surface already in the G-buffer (checking object ID/world position/normal) instead of re-shading, because re-running all effects at the end hit "can quickly become very expensive". [V] https://doi.org/10.1007/978-1-4842-7185-8_11 . Transparent shadows: any-hit accumulation `visibility *= 1 - opacity`, order independent, `RAY_FLAG_ACCEPT_FIRST_HIT_AND_END_SEARCH` still valid. [V] same chapter. UE: hardware RT translucency with "Max Refraction Rays" (default 3) and two-sided material recommended; a single ray leaves glass dark because the ray cannot exit; feature marked deprecated. [V via search snippet of UE docs: https://dev.epicgames.com/documentation/en-us/unreal-engine/hardware-ray-tracing-in-unreal-engine ; the page itself was not fetched, so [U] on wording].
2. **glTF mapping.** Full: `ior` drives Snell/Fresnel; `roughness` drives BTDF lobe sampling (`alpha = roughness^2`, IOR-scaled as in the Khronos shader) or a roughness-dependent ray cone; `thickness` ignored in favour of the true hit distance; `attenuationColor/Distance` give `sigma_t`; `dispersion` is one ray per channel (the Sample Renderer does three texture taps).
3. **Costs / limits.** See T2 numbers: 3 refractions required to resolve a glass in RTG II Fig. 29-1; 1.58 ms at 1080p RTX 2070 SUPER for a single object. [V] Limits: rays that exhaust the refraction depth look dark; a ray inside concave geometry needs 2+ events per object. Noise from rough lobes needs the denoiser (Phosphor has one for reflections).
4. **Sample Renderer.** Not applicable (rasteriser). The glTF spec already tells ray tracers to ignore the thickness map (above).
5. **Vis-buffer fit.** [A] Best architectural fit with what Phosphor already has: the existing RT reflection path generalises (new ray type that continues through the transmissive instance). The transmissive instance is flagged in the TLAS and *shaded as opaque in the primary vis-buffer* as a glass surface whose resolve does Fresnel mix of the reflection result and the refraction result (no second layer, no sorting). Problem cases: primary visibility needs the hit in the visibility buffer (so glass cannot be skipped by the raster pass, contrary to T1), refracted rays landing on another glass piece need a depth loop (cap 4, as UE uses 3). The residual "background through glass" needs a G-buffer-like radiance fetch for the end hit (RTG II ch. 11) or a one-bounce shading call; Phosphor's per-pixel surface guide buffer is the natural fallback target.

### T4. Hybrid: image-space first, ray-traced fix-up (Avalanche, RTG II ch. 29)

1. Image-space refraction (T2) to get the exit point, then 1-2 inline RT rays either before ("pre-rays", refract and trace into the scene first, then image-space to the back face) or after ("post-rays") it; inline ray tracing inside the pixel shader. Needs back-face depth+normal and TLAS. [V]
2. glTF mapping as T2/T3.
3. Costs: see T2 numbers. Quality limit: small visual differences near glass edges vs 3-ray pure RT. [V] (chapter abstract text via search + Fig 29-1 read)
4. n/a. 5. [A] Only worth it if pure RT 3-ray cost is over budget; Phosphor's F9 inline RT is already present.

### T5. Cheap/rejected baselines (for completeness)

- **IBL-only (Filament `cubemap`)**: transmits only the environment; Khronos explicitly warns it "will often fall short". [V]
- **Alpha-blended fallback** with `0 < alpha < 1`: Khronos' stated fallback when refraction is infeasible. [V] (Also the F16 OIT path.)
- **Weighted blended / depth-peeled OIT for transmission**: out of scope for F15 (F16); mentioned in RTG II ch. 29 as depth peeling (Krüger et al.) with failures on concave objects like a donut. [V]

## 2. Subsurface scattering (side-lit kings and queens, translucent wax/marble/stone)

Parameter note common to all: Burley normalised diffusion uses **surface (multiple-scatter) albedo `A`** and a **scattering distance/mean free path `d`**; the profile `R(r) = A s (e^{-sr/l} + e^{-sr/(3l)}) / (8 pi l r)`, `l` = mean free path, `s` = shape parameter. [V] (restated on slide 73 of Zhang & d'Eon, SIGGRAPH 2025 Advances, https://advances.realtimerendering.com/s2025/content/sss-siggraph-2025-advances-published.pdf). Disney's parameterisation used for path-traced SSS: `alpha = 1 - exp(-5.09406 A + 2.61188 A^2 - 4.31805 A^3)`, `s = 1.9 - A + 3.5 (A - 0.8)^2`, `sigma_t = 1/(d*s)` [V] (Chiang, Kutz, Burley, "Practical and Controllable Subsurface Scattering for Production Path Tracing", SIGGRAPH 2016 Talks, DOI 10.1145/2897839.2927433, https://media.disneyanimation.com/uploads/production/publication_asset/153/asset/siggraph2016SSS.pdf). The Khronos extension maps `multiscatterColor` (multi-scatter albedo) to single-scatter albedo with Kulla & Conty's fit `s = 4.09712 + 4.20863 rho - sqrt(9.59217 + 41.6808 rho + 17.7126 rho^2)`, `rho_ss = (1 - s^2)/(1 - g s^2)` and `sigma_s = sigma_t rho_ss`, `sigma_a = sigma_t (1 - rho_ss)`, with `sigma_t = -ln(attenuationColor)/attenuationDistance`. [V] KHR_materials_scatter README `a6cd5b4…`; same fit appears on slide 29 of the 2025 talk [V]. Scale: Khronos uses world-space `attenuationDistance` (metres); Standard Surface/MaterialX `subsurface_scale <= 0.01 m` [from the brief, not re-verified].

### S1. Screen-space Gaussian-mixture blur (d'Eon-Luebke, Jimenez 2009; "SSSS")

- Algorithm: after lighting, blur the *diffuse* irradiance with a sum of a few separable Gaussians (original 4-6, later 2 + a delta), depth-aware, in screen space, then add specular. [V description in Golubev 2018 slides (see S2) and Jimenez 2015]. Needs a diffuse/specular split lighting buffer, depth, stencil/material ID. Not retained as baseline; superseded by S2/S3.

### S2. Screen-space Burley normalised diffusion, importance-sampled (Golubev, Unity HDRP 2018; Xie et al. UE 2020)

1. **Algorithm / inputs.** [V] Golubev, "Efficient Screen-Space Subsurface Scattering Using Burley's Normalized Diffusion in Real-Time", SIGGRAPH 2018 Advances, https://www.advances.realtimerendering.com/s2018/Efficient%20screen%20space%20subsurface%20scattering%20Siggraph%202018.pdf (full text read via local text extraction):
   - *Lighting pass:* compute incident radiance at the entry point, apply diffuse transmission into the surface, apply entry albedo (pre/post-scatter texturing option), write to a subsurface-lighting target; stencil tagged with material type.
   - *SSS pass:* full-screen compute shader, bilateral filter of the radiance buffer around the exit point, apply exit albedo, diffuse transmission out toward the viewer; also merges diffuse and specular buffers.
   - Sample pattern **precomputed offline**: radial distances importance-sampled from the profile PDF (CDF inverted numerically with Halley's method), polar angle by Fibonacci spiral; **random per-pixel rotation** trades structured undersampling for noise (cleaned by TAA); samples re-weighted by the true Euclidean distance between entry and exit points (planar disk aligned to the screen plane, or tangent plane), weights normalised to sum to 1 (energy conserving). The disk is placed in the screen plane (0th order) or tangent plane.
   - Radius importance-samples the channel with the largest scatter distance. LOD: no filtering for sub-pixel disks, **21 samples** for medium footprints, **55** otherwise; PS4 limited to 21.
   - Hierarchical stencil culls whole tiles; LDS cache holds radiance + linear depth with a 2-texel border; Z-order thread layout.
2. **glTF mapping.** Diffuse albedo to `A`; `attenuationDistance * multiscatter-derived colour` or Standard Surface `subsurface_radius * subsurface_scale` to scatter distance `d` per channel; `multiscatterColor`/`subsurface_color` to `A`. This is exactly what the Khronos Sample Renderer implements (S5).
3. **Costs / limits.** Compute shader merging + convolution: **1.16 ms** with the setup shown in the talk; **GPU and resolution are not stated on the transcript** [V text; platform unspecified; the sentence follows the PS4 remark, so possibly PS4-class, [U]]. HDRP "High Quality" costs about 2.5x the default quality (official docs, https://docs.unity3d.com/Packages/com.unity.render-pipelines.high-definition@14.0/manual/Subsurface-Scattering.html [V]). Xie et al. (Epic, ACM CGIT 3(1), DOI 10.1145/3384536): single-pass variance-guided adaptive importance sampling in UE4, **2.78 ms vs 253.18 ms fixed 64 spp** on Quadro P4000, 1920x1080, close skin patch, bounds 8-64 spp [V via the authors' project page https://thisistian.github.io/publication/real-time-subsurface-with-adaptive-sampling ; paper PDF not read]. Jimenez 2015 separable SSS (CGF 34(6), DOI 10.1111/cgf.12529): **0.489 / 0.348 / 0.304 ms** at 1080p on Radeon HD 7970 for close/mid/long shot, two 1D passes, 7 samples per pixel, stencil culling [V] https://www.iryoku.com/separable-sss/ (paper PDF read locally).
   *Known limits (all V in Golubev's talk):* planar approximation, light bleeding across depth discontinuities mitigated but not removed by bilateral weights; **undersampling noise** in the (non-importance-sampled) lighting signal (a lit/unlit checkerboard breaks it), relies on TAA; kernels with very large screen footprint thrash the cache; "does not generalise to low-albedo materials like glass" (no specular transmission); thick-object translucency makes many assumptions. UE Subsurface Profile doc limits: no backscatter ("visible in a few cases such as ears"), grey outline when non-SSS materials occlude SSS, banding at large radii, Burley mode needs TAA. [V] https://dev.epicgames.com/documentation/en-us/unreal-engine/subsurface-profile-shading-model-in-unreal-engine
   *Thin-feature failure (important for chess pieces):* diffusion assumes a semi-infinite flat slab relative to the mean free path; on thin or highly curved geometry "diffusion keeps trying to scatter light as if it were still deep, and ends up overshooting" [V] Zhang & d'Eon 2025, slides 40-42.
4. **Sample Renderer: see S5.**
5. **Vis-buffer fit.** [A] Natural: the existing compute resolve already knows the material; make the resolve write **diffuse irradiance x entry albedo (as radiance) into a separate "subsurface lighting" target** only for SSS pixels (tagged in the surface guide buffer's material/profile id), keep specular/emissive separate, then run the compute bilateral pass and recombine. Phosphor composes `residual + DI + GI*diffuseAlbedo + specular`, so the diffuse part is *already separable*: the SSS target is `(DI_diffuse + GI) * albedo` for tagged pixels, and the convolution replaces just that term. Needs: depth (have), world/linear depth in LDS, a per-pixel profile id (the guide buffer), and a record of whether DI/GI are denoised before or after the blur (blur the denoised, pre-albedo irradiance if post-scatter texturing is chosen; avoids double blur noise). TAA/denoiser history interaction: the blur noise is the signal the existing denoiser should see, so blur *before* the final temporal stage.

### S3. Separable SSS (Jimenez et al. 2015)

1. Single 2D diffuse-reflectance kernel approximated by one separable pair (horizontal then vertical), axis-aligned pre-integration; a two-parameter artist model; jitter. [V] CGF 2015 (read). Inputs: diffuse/specular split, depth, stencil.
2. glTF mapping: scatter radius and colour as a "close fit" or "production" kernel (Table 2 of the paper: `sigma_n`, `sigma_f`, `w`); less physical than Burley, mapping from `attenuationDistance` is by hand.
3. Cost: see S2 (0.3-0.5 ms 1080p HD 7970). Limits: radial symmetry relaxed so kernel shape can show in extreme close-ups with high-frequency lighting (paper §Limitations). [V]
5. Same buffers as S2; cheapest but quality/physics below S2. Because Khronos picked Burley (S5), S2 is the better reference for compliance.

### S4. Translucency (back-lit thickness) layer on top of S2/S3: Jimenez 2010 and HDRP transmission

1. Light through thin parts: Jimenez et al., "Real-Time Realistic Skin Translucency", IEEE CG&A 30(4), 2010, uses a shadow-map-derived thickness (distance between shadow-map depth and the shaded point) fed into the diffusion profile (the paper's own text discusses translucent shadow maps and grown/shrunk shadow positions). [V partial; PDF skimmed https://graphics.unizar.es/papers/Real-Time-Realistic-Skin-Translucency.pdf]. HDRP (Golubev): thin objects use the Jimenez slab model with artist thickness map and a shared shadow fetch; thick objects take the **max of a shadow-map-derived thickness and the baked thickness texture**; "the method admittedly requires some tweaking". [V]
2. glTF mapping: `thicknessFactor/Texture` to thickness; `attenuationColor/Distance` to Beer-Lambert; `diffuseTransmissionFactor/Color` (or `KHR_materials_scatter` thin-walled mode, `scatterAnisotropy` splits forward `(1+g)/2` / backward `(1-g)/2`).
3. Limits: shadow-map thickness fails for fine features due to precision (Golubev); both transmission events evaluated in the lighting pass, "conceptually wrong" but visually close and avoids reading normals again. [V]
5. [A] With HW RT available, thickness `d` can be the *true* ray distance to the back face (a single "thickness ray" along `-n` or the refracted direction, accept-closest), replacing shadow-map tricks and giving correct occlusion of the back light by other objects (a shadow ray from the exit point toward each light, already what ReSTIR DI does).

### S5. Khronos Sample Renderer implementation of `KHR_materials_scatter` (reference for a glTF-conformant look)

All [V] at `cc3d5ff…`:
- **Pre-pass (`scatter.frag`, `renderer.js` ~L985-1050):** for each scatter drawable render *front-surface lighting* (diffuse IBL + punctual diffuse, no specular added back in as radiance) into an RGBA16F target, alpha = `materialID/255`; also a depth target; then a **back-face depth-only pass** (`scatter_back_depth.frag`, cull front) into a third target. Enabled only if `KHR_materials_transmission` and `KHR_materials_volume` are both enabled.
- **Multiple scattering (`punctual.glsl` `getSubsurfaceScattering`):** `scatterDistance = attenuationDistance * mix(multiScatter, singleScatter, abs(g))`, per-channel; screen radius from `scatterDistance / metresPerPixel` (computed from inverse projection at the pixel); if `maxRadiusPixels <= 1` returns the pixel's own value times colour; otherwise **55** precomputed samples (`scatterSampleCount = 55`, golden-angle spiral, `material.js` `computeScatterSamples`), same-material test via alpha ID, each weighted `burley_eval(d, |P_sample - P_center|) * rcpPdf`, final `sum(w*L)/sum(w)` times diffuse colour. `burley_setup(radius, albedo)`: `s = 1.9 - albedo + 3.5 (albedo-0.8)^2`, `l = radius/(4 pi)` , `d = l/s`; `burley_eval(d, r) = (e^{-r/d} + e^{-r/(3d)})/(4d)`.
- **Single scattering (`pbr.frag` `getVolumeSingleScattering`):** uses the **back-face depth** to get thickness along the view ray; refracts the view ray at the front normal (`refract(-v, n, 1/ior)`, TIR falls back to the unrefracted ray); converts to chord length `thickness / max(dot(refractedDir, viewRayDir), 0.05)` (planar-slab approximation "avoids depth peeling"); ray-marches `SCATTER_VOLUME_STEPS` steps with Henyey-Greenstein phase per punctual light (no shadowing inside the volume), IBL as isotropic `getDiffuseLight(n)/pi`, `inscatter *= sigma_s`, transmittance `exp(-sigma_t * t * (1 + cosRay))`.
- Final colour in the volumetric case = `singleScattering + diffuseScattering`, then the usual transmission path (volume attenuation of the refracted background, `thickness > 0`).
- **Thin-walled** (`thickness <= 0`): replaces the specular BTDF by `mix(BTDF, scatterLobe, scatterStrength)` where `scatterLobe = lightIntensity * NdotL(-n or n) * BRDF_lambertian(multiscatterColor) * (forward|backward fraction)` (`pbr.frag` ~L350-355, L520-545; IBL variant uses `getDiffuseLight(-n)`/`getDiffuseLight(n)`).
- This tells you the intended mathematical split: **multiple scattering = screen-space Burley diffusion** (needs a diffuse-lighting buffer + depth + ID), **single scattering + boundary term = analytic/ray-marched along the refracted ray using back-face depth**. It is the same split as Zhang & d'Eon 2025 (S6), except Khronos uses raster back-depth where they use RT.

### S6. Hybrid ray-traced single scattering + diffusion for multiple scattering (Zhang and d'Eon, NVIDIA, SIGGRAPH 2025 Advances)

1. **Algorithm** [V, slides read]: SSS is volume transport after a transmission event. Observation: zero + single scattering carry most of the signal when curvature is comparable to the mean free path; add a diffusion profile for higher orders. Boundary (zero-scatter) term analytic; single-scatter term sampled: after a transmission event refract into the volume (sample the transmission BSDF, which can be pure refraction or diffuse), cast a ray to get exit distance `d`, sample scatter distance `t` with `t = -ln(1 - xi(1 - exp(-sigma_t d)))/sigma_t`, sample the phase function, cast a second ray, evaluate the exit transmission and light sample (NEE). Cost 2 rays + 2 shadow rays per SSS vertex; also one diffusion-profile sample (a radius, a ray toward geometry, one explicit light sample). A **ReSTIR** variant picks the refraction direction from reservoirs using the boundary term as target (`p_hat = f`), 1 extra ray/frame, 3x3 spatial reuse; diffusion profile corrected by subtracting a *single-scattering profile* (Taylor expansion over single-scattering albedo, d'Eon 2022) to avoid double-counting; back-face irradiance screen-space cache; single-scatter-albedo demodulation before denoising.
   Inputs: TLAS, material albedo/mfp (`sigma_t`, `sigma_s`, `g`), area/many-light sampling (LTC irradiance + ratio shadow estimator, or ReSTIR-style light samples), a denoiser (DLSS-RR in the talk; separate demodulated denoisers earlier).
2. **glTF mapping.** Direct: `attenuationColor/Distance` to `sigma_t`; `multiscatterColor` plus `scatterAnisotropy` to `sigma_s`/`sigma_a` via the Kulla-Conty fit (identical to the Khronos extension).
3. **Costs.** **2.38 ms kernel time at 1080p with DLAA on an RTX 5090**, whole path-trace kernel for a 13.74M-triangle scene (7M hair), SSS vertex = 4 rays (2 shadow). [V] slide 81-85. Limits [V slides 86-87]: diffusion profile limits remain (colour mismatch with layered materials / extra specular lobe; missing high-order scattering for medium-density materials); quality scales with light sampling quality; diffusion was kept only for multi-scatter. Not a rasteriser-hybrid number: the 2.38 ms is the whole path-tracer kernel.
4. n/a.
5. **Vis-buffer / RT fit.** [A] The per-pixel SSS vertex (2 rays + 2 shadow) maps onto Phosphor's per-pixel ReSTIR DI surface guide: that buffer already has position/normal/material. A "boundary-term + single-scatter" pass needs per-pixel ray tracing from the exit point, and a constraint: Phosphor ReSTIR DI is evaluated at the *visible* surface; SSS needs light sampled at *other* points (the scattered entry point, the back exit point). Either re-run DI with a point-sampled guide at the secondary vertex (extra cost) or use a back-face irradiance cache like the talk. Needs denoise of the SSS signal (unlike the 5090 example, Phosphor's denoiser would need an extra channel). High implementation cost relative to S2.

### S7. Pure random-walk volumetric SSS (path traced; Chiang/Kutz/Burley 2016; UE Substrate "Simple Volume" is a different, analytic thing)

1. Offline-quality: random walk inside the closed volume with exponential free flights, MIS across colour channels (weight `f/p = sigma_s/sigma_t`). Real-time use limits the bounce count; Zhang & d'Eon say tracing a fixed small number of events is "much cheaper than unknown bounce counts" (slide 46) and show the 1-bounce result already captures most of the look (slide 44). [V] No shipped real-time hardware-RT random-walk SSS found [U].
2. glTF mapping: full (volume coefficients map directly). 3. Cost: no published real-time numbers found for pure random walk beyond S6. 5. [A] Not a baseline candidate; the reference for validation.

## 4. Recommendations (simple correct baseline and a higher-quality variant, each with its decision criterion)

All of this is [A], derived from the sources above.

### Transmission (glass pawn tops, liquids; closed convex meshes)

- **Baseline (B-T):** T1 + glTF-style thickness. Exclude transmissive primitives from the opaque vis-buffer; resolve/light the opaque layer as today; build a mip pyramid from the final composed HDR colour; draw transmissive instances in a forward-style pass using exactly the Khronos formulas: IOR-scaled roughness to mip LOD (`lod = log2(width) * roughness * clamp(2 ior - 2, 0, 1)`), refracted exit position `P + normalize(refract(-v,n,1/ior)) * thickness * modelScale` projected to the screen, `pow(attenuationColor, len/attenuationDistance)`, `* baseColor`. Light the glass surface for specular reflection with the existing RT/SSR/probe reflection path. Back-face depth (T2) can be added later with no change of architecture. Known and accepted limits: single layer, edge misses.
- **Higher quality (Q-T):** T3, ray-traced refraction using the existing RT reflection machinery: glass remains in the primary vis-buffer, refracted rays (cap 3-4 events as in UE and RTG II) continue through the glass volume with Beer-Lambert on back hits, end hits fetch radiance through the surface guide/composite radiance (RTG II ch. 11 G-buffer fallback). This also lets glass see other glass and the correct dark/bright backlit pawn tops.
- **Selection criterion (measurable):** render the same pawn-top and liquid test scene with the Phosphor RT path as reference (e.g. refraction depth 8, many spp) and compare B-T and Q-T by image difference on the transmissive-pixel mask (RMSE or HDR-FLIP/mean abs log-luminance error; threshold chosen when the plan is written), and by GPU ms at 1080p on M5 Max measured per the existing perf rules. Choose B-T when its error vs reference on the glass mask is under the agreed threshold *and* the scene never needs glass-through-glass or off-screen content; promote Q-T when B-T fails the threshold or when the frame budget has headroom for the measured extra RT ms. Per RTG II Fig. 29-1 the published ratio is about 1-3 ms vs 0.1 ms per object at 1080p on a 2070 SUPER, so measure on M5 before deciding; do not infer Apple numbers.

### Subsurface scattering (kings/queens: marble/ivory/wax-like, mm-scale radius)

- **Baseline (B-S):** S2 as implemented by the Khronos Sample Renderer (so results can be compared against a glTF-conformant viewer): resolve writes `(DI_diffuse + GI) * entry_albedo` to a subsurface-lighting target for pixels whose guide-buffer material id is SSS; compute pass does depth-aware Burley with 21/55 precomputed Fibonacci samples, per-pixel rotation, screen radius from `scatterDistance / metres-per-pixel` at that depth (sub-pixel radius = skip, exactly Khronos/Golubev), normalised weights, same-material test; then recombine with specular. Back-lit translucency (S4) via a thickness ray (RT) or the thickness texture and Beer-Lambert from `attenuationColor/Distance` plus `diffuseTransmission`/`scatter` thin-walled lobe, evaluated in the lighting pass. Parameters from `KHR_materials_scatter`: `sigma_t`, Kulla-Conty `multiscatterColor` to `rho_ss`, `scatterStrength`. At a few millimetres on a chess piece occupying a few hundred pixels, the filter footprint is a few pixels, so cost is low and bilateral depth weights matter more than sample count. Flag: thin parts (crown tips) violate the semi-infinite assumption (Zhang & d'Eon slides 40-42), so back-lighting must come from S4, not from the blur.
- **Higher quality (Q-S):** S6: keep the screen-space diffusion for multiple scattering and add ray-traced zero/single scattering from the exit point (boundary term analytic, single scatter with 2 rays + 2 shadow rays), with the single-scattering profile subtracted from the diffusion profile to avoid double counting. Needs light sampling at secondary vertices and a denoiser channel.
- **Selection criterion:** reference = high-spp random-walk render of the same king/queen meshes under a side light and a back light using Phosphor's own RT (S7, bounce cap high), compared on the piece mask; plus the sanity limit that mean luminance of lit and shadowed regions matches within an agreed tolerance (energy). Choose B-S when its mask error is within the agreed bound (reference: "Offline vs screen-space diffusion" comparisons in the 2025 talk show diffusion alone loses geometry detail near thin features); promote Q-S when error near thin/curved features (crown, fingers of the knight, edges) exceeds the bound *and* the measured extra ms (RT rays per pixel on piece pixels only) fits the F15 budget. For both, record GPU ms with `--gpu-timing-serial` at saturated clocks per the project rules.

### Cross-cutting requirements for Phosphor (derived)

- Every pixel needs a **material class** (opaque, SSS profile id, glass) in the surface guide buffer so the compute passes can early-out per tile (HDRP/Jimenez use stencil for the same purpose).
- The diffuse term must remain separable from specular all the way through denoising so the SSS blur sees *diffuse irradiance* (Phosphor's `GI*diffuseAlbedo` composition supports this).
- Keep alpha-test/OIT (F16) out of the transmission design: transmission as defined by Khronos is *not* alpha coverage (KHR_materials_transmission README states `alphaMode` is for coverage only). [V]
- Build the colour pyramid after composition, not from the unlit/forward colour; the Khronos renderer renders opaque and transparent drawables into the capture target before the transmissive draws (`renderer.js` L1134-1235). [V]
